# GAS（データの窓口）の設定手順

GitHub Pages の画面（ドリル・エディタ）から、今のスプレッドシートの Apps Script を使えるようにする手順です。
今の iPad の画面（GAS が配っている画面）は、切りかえが終わるまでそのまま動きます。URL も変わりません。

## A. 窓口を足す（1回だけ。clasp が使えるまでは手で貼る）

1. スプレッドシートの「拡張機能」→「Apps Script」を開く。
2. `コード.gs`（または `Code.gs`）の中身をすべて消し、このフォルダの `Code.gs` の中身を貼る。保存。
   - `index`・`editor`・`drillcore`・`theme` の4つは今のままでよい（中身は同じ）。
3. 関数の選択で `setup` を選び「実行」。下の「実行ログ」に次の3つが出る。
   - 管理用の鍵（今までと同じ）
   - **プレイヤー用の鍵（child）**：子どもの iPad に入れる鍵
   - **プレイヤー用の鍵（parent）**：保護者が遊ぶときに入れる鍵
   - 2つのプレイヤー用の鍵は、成績管理フォルダの `drill\記録の読み出し先.txt` に書き足しておく。
   - 「記録」シートの右に「プレイヤー」列ができる。今までの行（列が空の行）は子ども（child）の記録として扱う。
4. 「デプロイ」→「デプロイを管理」→ 鉛筆マーク →「バージョン」で「新バージョン」→「デプロイ」。URL は変わらない。

## B. clasp が使えるようになったら

`gas/` フォルダで `clasp clone <スクリプトID>`（または `.clasp.json` を作る）→ `clasp push` → `clasp deploy -i <デプロイID>`（同じURLのまま新バージョン）。
`.clasp.json`・`.clasprc.json` はコミットしない。

## C. 画面（GitHub Pages）

- `config.js` の `gasUrl` に、ウェブアプリの URL（…/exec）を入れる。URL は秘密ではないが、鍵はここに書かない。
- 記録はプレイヤーごとに別々（問題は共通）。どのプレイヤーかは入れた鍵で決まる。
- 子どもの iPad：Safari で `https://ozackdown0925-web.github.io/brain-dungeon/drill.html` を開き、プレイヤー用の鍵を1回入れる。そのあと「共有」→「ホーム画面に追加」。
  - ホーム画面から開いたときに、もう一度鍵を聞かれることがある（Safari とホーム画面で覚える場所が別のため）。そのときはもう一度入れる。
- 保護者が遊ぶとき：同じように開いて、保護者の鍵（parent）を入れる。見出しの横に「（保護者）」と出る。
- 問題エディタ：パソコンで `…/brain-dungeon/editor.html` を開き、管理用の鍵を入れる。

## 窓口の一覧（画面からは POST、Content-Type: text/plain、中身は JSON `{ key, action, ... }`）

| action | 鍵 | 中身 | 返事 |
|---|---|---|---|
| check | プレイヤー／管理 | | `role`（player / admin）、`player`（child / parent） |
| drillQuestions | プレイヤー／管理 | | `questions`（出題するものだけ） |
| image | プレイヤー／管理 | `id` | `src`（data URL） |
| history | プレイヤー／管理 | | `records`（そのプレイヤーの分だけ）、`player` |
| saveAnswer | プレイヤー／管理 | `record` | （そのプレイヤーの記録として保存） |
| questions | 管理 | | `questions`（すべて） |
| saveQuestion | 管理 | `question` | `question` |
| deleteQuestion | 管理 | `id` | |
| uploadImage | 管理 | `dataUrl`, `name` | `id` |
| export | 管理 | `player`（省略すると child） | `records` |
| import | 管理 | （今まで通り。upload.py 用） | |

- 返事は `{ ok: true, ... }` か `{ error: "…" }`（鍵がちがうと `forbidden`）。
- 読むだけのもの（check・drillQuestions・image・history）は GET `?action=…&key=…` でも使える。
- プレイヤーは鍵で決める。画面から player は送らない（管理用の鍵のときだけ `player` を指定できる。省略すると child）。
- `?action=export&key=…` は今まで通りの形で、子どもの記録だけを返す。`&player=parent` で保護者の分、`&player=all` で全員分（各行に `player` が付く）。
- 今までの `?action=export&key=…`・`?action=questions&key=…`・POST `action=import` は形を変えていない。
